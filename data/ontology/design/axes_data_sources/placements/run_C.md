# Data sources — placement run C

#102 step 4. One of three independent placement runs over
`placement_candidates.tsv` (194 names). I read, in order: `METHOD.md`,
`SYNTHESIS.md`, `access/nodes.tsv`, `provenance/nodes.tsv`,
`placement_candidates.tsv`, and #102 Parts A and E. **I did not look for or read
the other two runs' outputs**, and nothing else in the repo was opened.

Conventions used throughout:

- **`access` is a property of the mention**, so for a *name* I record the value
  set the name can legitimately take with the typical one first: `interactive
  (typ) | fixed` means "normally stepped online, but a paper training on a
  frozen log of it correctly reports `fixed`". A name with one value listed is
  one where I can find no legitimate second reading.
- **`provenance` is a property of the entity** and multi-valued, so it is a set.
- `~` prefixes a value I would only assign with the paper in hand.
- 194 candidates = **22 rejected** + **172 placed**.

**The measured cost of this clause, which Part E says is ~1.6% of names

are simulation sources** (#2, #11, #12, #15, #16, #17, #18, plus #5/#6 as
generated grid data) and **three of the three** industrial RAN/5G simulators in
the candidate set are rejected — spared only where a brand exists
(`FDA-approved UVA/Padova …`, admitted). This is run A's recorded prediction
that *"the named threshold biases the survey toward public-benchmark compute and
away from private collection and simulation"*, measured on a real list: the
clause deletes industrial and in-house simulation almost completely while
touching no public benchmark.

### 1b. Part A, "the software that implements a source" — 3 names

| # | name | why |

**`MuJoCo` is tied for the most frequent name in the whole candidate set (10
papers, level with `DeepMind Control Suite`) and clause 1b rejects it.** In 10 papers the mention says only
"MuJoCo"/"Mujoco environments" — there is no named task to re-point it at
(quotes: *"empirically demonstrate in both tabular and Mujoco environments"*,
*"33 tasks from DeepMind Control, MuJoCo, MetaWorld, and Box2D"*). Counting
names 8–10 and 19, **clause 1b plus clause 1a removes 4 names and ~13 paper
mentions with no admissible referent to inherit them.** The clause is right
ontologically and leaves those mentions uncodeable; that trade is not recorded
anywhere in #102 and should be.

## 3. Tensions

The order is the one the task asks for: a missing value, an unbreakable tie, an
undecidable name, contradictory tests, and `derived_from` carrying the axes.

### T1 — a name that needs a value no node supplies: **the protocol-only benchmark (22 names)**

The largest single finding in this run. These names denote an artifact whose own
contribution is **a protocol, a selection or a budget over sources it did not
produce**:

```
HELM · CrossFit · SubpopBench suite · T0 task suite · OpenML-CC18 · OpenML-CTR23
Unsupervised Reinforcement Learning Benchmark (URLB) · Unsupervised RL Benchmark (URLB) · URL Benchmark
Real-World Reinforcement Learning Benchmark (RWRL) · Real-World RL benchmark · EARL benchmark
Atari 100k · Atari 100k benchmark · 100k benchmark · Atari 2600 benchmark · Atari Benchmark
Sequential Arcade Learning Environment · CARLA NoCrash benchmark · MiniGrid benchmark
Gym MuJoCo Benchmark · Reddit FL benchmark dataset
```

URLB says so in its own quote — *"established a common protocol to compare
self-supervised algorithms across several domains and tasks from the DMC
Suite"*. `Atari 100k`'s entire content is "26 games, 100,000 interactions".
`Reddit FL benchmark dataset`'s contribution is a *partition by user*.

The problem is structural, not cosmetic. Part D assigns the
evaluation-protocol half of a suite to algorithms `R.eval`, so after that
half is removed **this dimension has nothing left to say about 22 of its 172
names** — it must still give each a non-empty `access` and `provenance`, and
both are simply inherited from the underlying source. A reader counting
"interactive sources" counts ALE six extra times.

I am **not** proposing a value be added on either axis for this: a protocol is
not a supply mode and not a generating process, so it would break both
principles of division. What it wants is either a **relation** — the shape
`derived_from` already has, say `protocol_over` — or an admission-rule clause
saying a protocol-only benchmark is not a data source and its mentions resolve to
the sources it selects. That choice is above this run's pay grade, but the
measurement is not: **22/172 = 13%.**

### T2 — three more values no node supplies, each with few names

- **`Hopper Controller` → `provenance-other`.** The examples are 3,200
  neural-network weight vectors with simulated returns. The weights are **the
  output of an optimisation run**: `model-generated` fails its test (nothing was
  sampled or predicted *by* a model — the weights *are* a model),
  `constructed` fails (no specification is the ground truth), `simulated`
  covers only the return. This is the only firm `provenance-other` in the set,
  and it is **not** the telemetry case the node's note anticipates. If
  design-bench-style offline optimisation is common in the corpus, "the output
  of a training run, used as data" is a candidate value; on one name I only
  record it.
- **Sample budget / boundedness.** `Atari 100k`, `Atari 100k benchmark`,
  `100k benchmark` carry *only* this; `Procgen` (unbounded levels), `TextWorld`,
  `RB benchmark`, `Kuhn Poker` and the two arithmetic benchmarks carry it as
  well. Run A's `supply` axis, confirmed on 9 names.
- **`elicited` is human-scoped and animals fall out.** `Neural Latents
  Benchmark` is monkey motor-cortex recording during a *cued* task: the
  behaviour exists because the experiment asked, but the node reads "Elicited
  from people". One name here; in a neuroscience-heavy corpus it will not stay
  one.
- **Availability is in the names themselves.** `FDA-approved UVA/Padova …`,
  `5G Proprietary System-Level Network Simulator`, `Proprietary System Level RAN
  Simulator Dataset` put governance/licensing *in the string*. 3/3 predicted
  coders would mis-code `access` as openness; this is stronger evidence — the
  field writes availability into the name, so there is no name-level step at
  which the coder is not tempted.

### T3 — a tie no node test can break: **`generator` vs `interactive` (22 names)**

```
MiniGrid · MiniGrid benchmark · BabyAI · Procgen · Procgen Benchmark · ProcGen CoinRun
Procgen-Maze · Hypergrid Environment · TextWorld · NetHack Learning Environment (NLE)
Kuhn Poker · Leduc Poker · Gibson Environment · CARLA · RB benchmark

```

Both positive tests pass, on different units. `generator`: *"asking for twice as
many returns twice as many valid non-duplicates; a seed or config change yields
fresh examples"* — true of a Procgen *level*. `interactive`: *"the consumer's
choices change which examples come to exist, and `reset` is a distinct
operation"* — true of a Procgen *step*. And `generator`'s negative test
(*"fails if what arrives depends on what the consumer just did"*) and
`interactive`'s negative test (*"fails if the examples would be identical
whatever the consumer emitted"*) **both fire**, each against the other.

The resolution is not in the axis: it is that the two values measure different
units (an episode vs a transition), and `access` is single-valued by design so
that the example count stays recoverable. `TextWorld` is the name that makes it
undeniable, because its own description — *"a platform for generating synthetic
worlds"* — puts `generator` first while every episode is interactive. **I record
the tie and do not break it.** Per METHOD, the corpus does not arbitrate.

### T6 — released but not named: `Generated Datasets from DeepMind Control Suite`

*"Our learning code, generated datasets, and custom continuous control
environments … are publicly available at: https://sites.google.com/view/…"* —
downloadable, citable, reused, and nameless. Part E's criterion is *"a
derivation earns an entity when it is named as an artifact"*, and clause 1a
rejects descriptions. So this artifact is rejected for lacking a name it was
never given, while the functionally identical `Atari DQN replay dataset` is
admitted because someone wrote a title. The criterion is cheap to apply and it
is measuring publication conventions, not ontology. `DeepMind Control Suite
(DMC)`'s own quote shows the same hole from the other side: *"We also created a
dataset from the DMC environments following the same procedure as … D4RL"* — a
`fixed` mention whose entity does not exist.

### T7 — the simulator/data naming inversion: `… from SERGIO`, `… from NEST`

`Gene Regulatory Network Simulation Data from SERGIO` and `Neuronal Network
Simulation Data from NEST` name **the software and describe the data**, which is
the exact inverse of what clauses 1a and 1b assume. Read strictly: the data half
is an unnamed description (reject) and the software half is a library (reject),
so the source is admissible as neither — yet a GRN simulation is as much a data
source as `HalfCheetah`.

The criterion that makes clause 1b work for MuJoCo does not generalise. MuJoCo
is a library because the *task* — body, reward, horizon — is authored by someone
else into a named artifact. But NEST and SERGIO are also parameterised by a
model the user authors, while `CARLA` ships its towns and is listed in the
axis's own `simulated` examples. So the real line is **"does the named thing
ship the model, or only the solver"**, and neither #102 nor the axis files state
it. On this list it decides 5 names and it is undecidable from 3 of them.

1. **The speculative flag is confirmed as a coherence question, not a rarity

   *exclusive* territory: on 30 of those 37 the competitor is `constructed`,
   which is exactly the A/C-versus-B divergence SYNTHESIS §2 recorded, now
   with 30 names behind it instead of an argument.
2. **The 4 firm cases are the ones B's argument predicted and A/C's did not
   cover.** `Poker Hand` and `IMDB-Wiki` are *labels computed by a written rule
   over content with an empirical referent* — real dealt hands, real
   photographs — so `constructed`'s "no empirical referent" is false of them,
   precisely B's unit-test argument transposed. The value earns its keep on
   non-game cases; on games it is a coin flip.
3. **The two groups want different answers.** A grammar-generated string set
   (CFQ, Juliet) is `constructed` *and* rule-produced with no tension worth
   resolving — the spec is the ground truth and the spec is a rule. A rule-
   computed *label over real content* (Poker Hand, IMDB-Wiki, ExtremeWeather,
   CANUE, Stockfish) is `rule` and nothing else fits. If the value is ever
   narrowed, the test to narrow it to is "the rule produced the **target**, not
   the **input**" — which is the channel-scoping fix SYNTHESIS §3 proposes 3/3,
   arriving again from a different direction.

### M4 — `stream`: **0 names, as expected, and not evidence**

No name in the 194 is `stream` in any mention. Two names *could* be
(`Wikipedia` via recent-changes, `Common Crawl` as a live crawl) and both appear
as snapshots: *"18 snapshots archived by Common Crawl in 2020 and 2021"*. That
is 3/3's prediction — "the snapshot is what gets the name" — reproduced
verbatim in a corpus quote.

Per the node's own note and METHOD §1, **I draw no conclusion against the value
from this.** Two observations that do carry information:

- **The near-miss is a mis-coding trap, not a gap.** `Poker Hand`'s quote says
  *"are originally multiclass data **streams**"* — the concept-drift sense: a
  fixed file replayed in order, which is `fixed`. The only occurrence of the
  word "stream" in the whole candidate set is on a name that is not `stream`. A
  coder matching on the word gets it wrong on 1 of 1.

  this list's queryable sources are all *also* downloadable, so the mention is

### M5 — `simulated` / `constructed`: **it bites on 75 of 172 names (44%), in five distinct mechanisms**

The boundary all three phase-1 runs flagged is the single largest placement
problem in this set — larger than every other tension except T1, and unlike T1
it is on the axis itself.

| # | mechanism | names | why both values hold |
|---|---|---|---|

Total **75**. One name sits on a *different* edge of the same cut and is worth
naming separately: **`Gibson Environment` = {natural, simulated}** — pure laser
scans of real buildings, then rendered, with no authored content at all. That is
the `natural`/`simulated` boundary rather than `simulated`/`constructed`, and it
is the only name in the set on it. `Habitat Pick` straddles all three.

Four more names carry the M5-5 mechanism and I resolved them to `simulated`
alone, because the solver's real referent dominates and the generated
configuration is a *parameter draw* rather than content:
`Neuronal Network Simulation Data from NEST`, `CAMELS suite`,
`NeuroTouch FEM simulation dataset`,
`FDA-approved UVA/Padova Type1 Diabetes Mellitus Simulator`. Each would flip if
the paper generated its network, cosmology or virtual-patient cohort
synthetically, which the names do not say (T8).

Seven names are **clean `simulated`** with no boundary problem, and all seven
have an unambiguously real, specific referent: `Fast Folding Proteins
Benchmark`, `CityLearn`, `ExtremeWeather`, `Neuronal Network Simulation Data
from NEST`, `CAMELS suite`, `NeuroTouch FEM simulation dataset`,
`FDA-approved UVA/Padova Type1 Diabetes Mellitus Simulator`. Clean `constructed` runs to the grid
and card worlds (`MiniGrid` family, `Four Rooms`, `Procgen` family, poker,
`BSuite`, `Mandl benchmark`).

**What the 75 names say about the axis.** The cut is not failing — it is cutting
*one source into two layers*, and almost always the same two: **a physics layer
with a real referent and a content layer without one.** That is run A's
alternative verbatim — one `program-computed` value plus a separate `referent`
axis — reached here from placement pressure rather than from derivation. With
75/172 names carrying both values the practical cost today is low, because
"carries both" is a perfectly good answer under non-exclusive counting; the cost
is that **`simulated` and `constructed` cannot be used as a partition of the RL
corpus for any roll-up**, and someone will try.

I am not proposing the merge. Per METHOD, three runs reached these two values
independently, agreement is the evidence, and a placement run does not get to
undo that. What a placement run can do is say how often the two co-occur, and
the answer is: **on 44% of admitted names, and on 73 of the 103 RL
environment names (71%).**
